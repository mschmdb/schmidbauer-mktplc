# SvelteKit / Svelte 5

**Applies when:** the diff touches `.svelte`, `.svelte.ts`, `.svelte.js` files, or files named `+page.*`, `+layout.*`, `+server.*`, `hooks.server.*`, `hooks.client.*`.

## Extra excludes

- `**/.svelte-kit/**`
- `**/src/lib/paraglide/**` (generated by Paraglide i18n, if used)

## Escalation patterns

| Pattern | Reason |
|---|---|
| path `**/hooks.server.*` | server hook change |
| path `src/lib/server/**` | server-only module change |
| added line contains `event.locals` together with `session` or `user` | session handling change |
| added line contains `{@html` | raw HTML sink |

## Review checklist

- Runes are used correctly: `$state`, `$derived`, `$effect`, `$props`, `$bindable`. New code has no legacy `$:` reactive statements and no `export let` props.
- `$effect` is not used where `$derived` would do. Effects that write state they also read can loop.
- Server/client boundary: secrets only in `+page.server.*`, `+layout.server.*`, `+server.*`, `src/lib/server/**` or `$env/*/private`. Nothing from these reaches client bundles.
- `load` functions have no side effects, return serializable data, and call `parent()` only when needed (it serializes the waterfall).
- Form actions validate input on the server; progressive enhancement via `use:enhance` does not skip validation.
- Mutating endpoints (`+server.*` with POST/PUT/PATCH/DELETE) check authorization themselves; they do not rely on the page having checked it.
- `{@const}` is the direct child of a block (`{#if}`, `{#each}`, `{#snippet}`, a component), not a top-level construct.
- Snippets and `{@render}` replace slots in new Svelte 5 code.
